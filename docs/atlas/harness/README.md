# Atlas manual harness · v1

This branch is the control plane. `state.json` holds the A–E team adapters, immutable baseline SHAs, original metrics, separate extended metrics, prioritized lanes, dependency IDs, native queues, and validator commands. The original assignments remain at `assignment_sha`. Read the original assignment and the native checkpoint and acceptance files named in your adapter at their pinned commits. The team branches own their datasets and remain independent. Use [LAUNCH.md](LAUNCH.md) to start a fresh chat. No scheduler, external service, or persistent session is needed.

## Roles and dispatch

| Role | Authority |
|---|---|
| Global planner | Read GitHub refs, PRs, team manifests and unresolved dependencies. Report one bounded candidate or escalation. |
| Team planner | Verify the exact native queue row, its source IDs and current eligibility. Choose one case from the highest-priority actionable lane. |
| Researcher/developer | With explicit dispatch for that case, prepare scoped changes and provenance. Stop at the packet boundary. |
| Verifier | In a separate fresh read-only session, reproduce source and native checks from pinned inputs. Return scoped findings or a blocker. |
| Canonical writer | One PortalHunter-designated writer session per team at a time. Only this session may publish validated changes under its team root. |
| Integrator and QA (E) | Independently audit immutable A–D inputs and return discrepancies to owners. Write only to an authorized E branch under its own root. |
| Master maintainer | Update the architecture branch state and global receipts after readback. Report by team and gate, without aggregating incomparable metrics. |

GitHub account access does not designate a writer session. The maintainer names the one writer when launching it and keeps other sessions read-only. C follow-up is held pending explicit scope after the completed discovery handoff. E is available for read-only planning. Provision E separately under its original assignment when authorized, and reconcile its pinned A–D inputs before integration. ## Start, stop and reconcile

Before research dispatch use [the checkout ledger](CHECKOUT.md). A team chat must read back its own atomic start transition before beginning its case. The librarian releases slots after independent check-in.

1. Read the master ref, then use its immutable SHA. Fetch the target team ref and PR independently. Confirm branch, live SHA, write authority, and open/draft/unmerged state. A moving head, unavailable permissions, or a closed/ready PR stops dispatch. If the live SHA differs from the master snapshot, inspect the intervening diff, rerun or qualify the metrics and validator, and reconcile the current checkpoint and queue. The master maintainer may refresh the pinned state with its own lease. A planner can use a reconciled live SHA for a packet when the adapter still applies, documenting the reconciliation. Escalate ownership, branch or queue-contract changes to the master maintainer.
2. Run `python3 harness.py TEAM` from this directory to see ordered eligible lanes. Resolve one exact native row at the verified team head using the native key or a unique composite key. Verify active dependencies from their immutable closure records. Skip closed or in-flight cases. Read the branch's `runs/` manifest history and native outcomes, including historical outcomes before v1. Use a deterministic filename-safe case key from the native identity (hash the stable composite key if needed). Preserve the full row key. The same lane and case reuse the same logical key.
3. Stop after one case, on ambiguity, missing evidence, failed verification, stale head, or ownership conflict. Preserve the prior outcome. Reopen only when a named condition is met, with maintainer approval and an immutable reference to the prior blocker and new trigger. Keep the stable logical key. Preserve the preceding manifest in Git history and append the reopening receipt to the new manifest validation log. Only an independently verified reopening may omit that key from the occupied set.
4. Preserve original acceptance criteria separately from extended programmes and counters. Do not advance clinical, legal, rights, ancestry or governance status through an architecture, metadata or structural check. Keep original source and translation, issuer, location, jurisdiction, population, dates, effective scope, access type, contradictions and retention limits distinct. A lead, index, abstract, catalogue, directory, organizational membership, or machine consolidation cannot stand in for an authenticated original instrument or scientific appraisal. Verify originals at the exact passage/table, version, issuer and date with independent review. Record unresolved historical, territorial, disputed-sovereignty, Indigenous/community authority, cross-border, study population and clinical limits. Keep private records and restricted copies out of the repo. Expert approval remains a separate decision.

## Shared packet, manifest and receipt contracts

The executable v1 schema is in `harness.py`. Run `python3 harness.py TEAM --live-sha LIVE --packet packet.json --result result.json --receipt receipt.json` with only the files available at that stage. Use `--occupied` for existing logical keys and `--completed` for independently closed dependency IDs. The CLI is structural. The planner and verifier must check actual queue row identity and live GitHub permissions themselves.

- **Packet** includes `version` (1), `task` (lane ID), `case` (stable normalized key), `expected_sha`, `queue_path`, `row_key` (exact native key or composite), `evidence_required` (true), and `paths` (exact allowlist including the manifest). Pin any cross-team reference by commit and path. Keep session scope to this packet.
- **Result** includes `version`, `key` (lane:case), `input_sha`, `disposition` (`verified_scoped`, `blocked`, or `no_change`), `evidence`, `blocker`, `reopen`, `validation` (nonempty strings), and `paths` (actual changed paths). Each evidence object has `id`, `url`, `locator`, `issuer`, `checked`, `original` (boolean), `access` (`direct`, `indexed`, `blocked`, or `metadata`), and `qualification`. Record native row key, independent verifier reference, commands/exits, limitations, original and extended before/after counts or immutable metric references in the validation log. A blocked/no-change write is checkpoint-only. Persist the result at `runs/LANE--CASE.json` under the owning root.
- **Receipt** includes `version`, `key`, `commit`, `parent`, `paths`, `blob_shas` (path → SHA), and `pr_state` (`open/draft/unmerged`). A read-only verifier independently retrieves the commit, parent, complete changed paths, tree and blobs by SHA, checks expected bytes, and confirms the live PR/head. Store the receipt with the global checkpoint in a later master commit or report it directly with immutable links. A result cannot self-certify its own commit SHA.

## Publish once

Use a single commit directly parented by the verified expected SHA. Check actual diff paths and modes against the packet before publishing. Reject symlinks, submodules, deletes or renames unless explicitly authorized in a newly verified packet. Update the authorized branch with atomic expected-SHA enforcement (Git explicit `--force-with-lease=refs/heads/BRANCH:EXPECTED` after proving the new commit is a direct child, or GitHub expected-SHA ref update with force disabled). A preliminary read alone is insufficient. Never overwrite, rebase away or reset concurrent work. On lease failure, independently read the new head and compare the case key, evidence and paths. If already saved identically, return the existing receipt. If still eligible, create a new packet against the new SHA only after reconciliation. If conflicting or unclear, stop and escalate. When the connector cannot enforce the lease, leave the verified packet uncommitted.

Independent readback and the draft PR check finish the run. Report team, case, outcome, input/output SHA, original and extended deltas, native check results, blockers, and next eligibility. Never merge or mark ready through this harness. Keep `main`, site, calculator, production logic, and foreign team roots outside the write set. A verifier can independently rerun `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v` from this directory using synthetic fixtures alone.
